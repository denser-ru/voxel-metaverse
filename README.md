## 📖 Часть 1. Философия и Концепт Экосистемы (The Vision)

### Проблема: Синдром «Обезьяны с очками»
Современная индурия ИТ-образования для детей попала в ловушку дешевого дофамина. То, что сегодня продается под вывеской «Обучение программированию в Minecraft» — это суррогат. Ребенку дают скопировать кусок готового бойлерплейта, он нажимает `Run`, и на экране взрывается тысяча блоков динамита. 

Ребенок чувствует себя хакером, но знания не становятся отчуждаемым навыком. Без мишуры игры он не может написать даже простейший цикл. Это карго-культ, где вместо инженерии преподают нажатие на правильные кнопки.

### Наше решение: «Троянский конь Computer Science»
Voxel Metaverse — это не игра. Это **математически строгий воксельный дисплей**, периферийное устройство для визуализации того, как работает человеческая мысль, выраженная в коде. 

Мы упаковываем фундаментальную, жесткую инженерию в форму, от которой подросток физически не сможет отказаться. Ребенок думает, что он пишет «легальный чит-код», чтобы строить алмазные замки одной кнопкой. А на самом деле он прямо сейчас осваивает:
* **Infrastructure as Code (IaC):** Алгоритм идемпотентен, код приводит участок к идеальному результату.
* **Инкапсуляцию и ООП:** Класс — это чертеж, а робот-черепашка — конкретный инстанс с состоянием `(x, y, z)`.
* **Сетевые протоколы и распределенные системы:** Код работает на домашнем ноутбуке, а рендерится в облаке.

### Ключевые инновации платформы

1. **Zero-Install Showcase (Социальный триумф по ссылке)**
   Мы уничтожили барьер входа. Чтобы показать свой код друзьям, ученику не нужно заставлять их покупать игру, ставить Java или настраивать порты. Он просто кидает ссылку в Telegram: `https://play.domain.com/?plot=12`. Друг кликает по ней на смартфоне, загружает Wasm-движок прямо в браузере и мгновенно оказывается на участке в режиме зрителя (Spectator).
   
2. **Record & Replay (Вечная Офлайн-Витрина)**
   Архитектурный паттерн «Магнитофон». Поскольку Python-скрипт ученика исполняется локально, он не может работать 24/7. Но когда ученик запускает код, сервер *записывает* все успешные шаги в оперативную память. Когда зритель переходит по ссылке ночью, сервер автономно проигрывает эту "пленку" (Tape), восстанавливая постройку блок за блоком.

3. **Fail-Fast & Цена Ошибки**
   Робот — не магическая палочка, а физический механизм. Если скрипт ученика содержит ошибку и робот врезается в стену, выполнение не игнорируется. Клиентский SDK мгновенно падает с исключением на родном языке ученика. Мы не скрываем ошибки, мы учим их читать и обрабатывать.

## 🏗️ Часть 2. Макро-Архитектура и Сетевая Топология (The Architecture)

### Разделение ответственностей: Отказ от монолита
Классическая ошибка любительских проектов на базе воксельных игр — попытка запихнуть интерпретатор Python внутрь игрового сервера (через тяжелые моды вроде RaspberryJuice). Это создает архитектурный кошмар: выполнение непроверенного детского кода в основном потоке игры роняет сервер, сборщик мусора блокирует физику, а сервер превращается в уязвимого монстра (God-Server).

Мы реализовали строгое **сетевое разделение на Model-View-Controller (MVC)**:
* **Controller (Мозг):** Локальный интерпретатор Python на компьютере ребенка. Здесь живут циклы, условия, память и математика. Питон ничего не знает о 3D-движках.
* **View (3D-Дисплей):** Выделенный headless-сервер Luanti (C++/LuaJIT). Он ничего не знает о Питоне. Сервер выступает как «глупый 3D-монитор» и физический валидатор: он принимает координаты по TCP, проверяет границы и рендерит блоки.

### Физическая топология системы

```text
+-------------------------------------------------------------------------+
| ОБЛАЧНЫЙ СЕРВЕРНЫЙ КОНТУР (Docker / VPS)                                |
|                                                                         |
|  +-----------------------+           UDP :30000    +-----------------+  |
|  | Nginx + Websockify    | <---------------------> |                 |  |
|  | (Раздача Wasm + Мост) |                         |  Luanti Server  |  |
|  +-----------+-----------+                         |  (Headless 5.8+)|  |
|              |                                     |                 |  |
|              |                                     |  +-----------+  |  |
|              |                                     |  | Lua Mod:  |  |  |
|              |                                     |  | voxel_bot |  |  |
|              |                                     +--+-----+-----+--+  |
+--------------|----------------------------------------------|-----------+
               | HTTP / WS :8080                              | TCP :4711
               | (?plot=12&guest=true)                        | (NDJSON RPC)
               v                                              v
+------------------------------+               +--------------------------+
| ЗРИТЕЛЬ / ГОСТЬ              |               | РАБОЧЕЕ МЕСТО УЧЕНИКА    |
| Любой браузер (Mobile / PC)  |               | Локальный ПК             |
| (Luanti WebAssembly Client)  |               | IDE + voxel_turtle.py    |
+------------------------------+               +--------------------------+
```

### Сетевая матрица и транспортные протоколы

Вся коммуникация между узлами системы сведена к трем строго изолированным каналам:

| Порт / Протокол | Направление | Роль в системе | Архитектурная защита |
| :--- | :--- | :--- | :--- |
| **`4711` / TCP** | Ученик $\rightarrow$ Сервер | Канал управления Черепашкой. Потоковый **NDJSON** (JSON Lines с разделителем `\n`). | Неблокирующий ввод-вывод (`settimeout(0)`). TCP Backpressure отсекает спам-циклы. |
| **`30000` / UDP** | Сервер $\leftrightarrow$ Мост | Нативный бинарный трафик движка Luanti. | **Изолирован.** Порт спрятан внутри Docker-сети и не торчит в публичный интернет. |
| **`8080` / HTTP+WS** | Гость $\rightarrow$ Сервер | Единый публичный веб-шлюз. Раздача Wasm-клиента и WebSocket-проксирование трафика. | Агрессивное кэширование Wasm-бинарников в Nginx. TLS-терминация. |

### Инженерные инварианты отказоустойчивости (Safety Guardrails)

Чтобы платформа выдерживала сотни одновременных ученических скриптов, в ядро симуляции заложены четыре фундаментальных барьера:

1. **Non-blocking I/O:** Серверный мод обрабатывает входящие TCP-команды в рамках игрового тика (`globalstep`). Если клиент лагает или оборвал связь, сервер не ждет его, предотвращая просадку TPS (Zero-Lag Policy).
2. **Time Slicing (Нарезка времени):** Команда массовой застройки (`bulk_set_nodes`) на 10 000 блоков не ставит все блоки разом. Мод рубит массив на чанки по 500 блоков и выставляет по одному чанку за тик, сохраняя стабильные 60 FPS для зрителей.
3. **In-Memory Delta Rollback:** При запуске демо-режима для зрителей сервер не сохраняет схемы на жесткий диск (что вызывало бы спайки I/O Wait). Дельты измененных блоков пишутся в оперативную память Lua, позволяя мгновенно откатить участок в исходное состояние без обращений к диску.
4. **Невидимые барьеры (Griefing Protection):** Каждый участок $32 \times 32$ окружен физической невидимой стеной (`voxel_bot:barrier`) до высоты $Y=63$. Ни один скрипт не может залить соседний участок лавой или сбросить туда песок.

## 📁 Часть 3. Анатомия Монорепозитория: Мультиагентные Workspaces

### Почему монолитная документация мертва в 2026 году
Традиционный подход к документированию (свалка текстов в одной папке `docs/`) не работает в эпоху автономных кодинг-агентов (Antigravity, Cursor, Claude Code). Если скормить агенту весь проект целиком, наступает **распад контекста (Context Decay)**: агент, пишущий на Python, начинает пытаться импортировать библиотеки из C++ движка, а агент, настраивающий Nginx, пытается оптимизировать игровую физику.

Этот репозиторий разделен на **5 изолированных рабочих пространств (Bounded Contexts)** с глухими перегородками. Агенты запускаются строго внутри конкретного Workspace и физически не видят внутренности соседних модулей.

```text
voxel_metaverse_project/
├── workspace_0_shared_contracts/   # 📜 Ядро: Единый сетевой язык (Source of Truth)
├── workspace_1_python_sdk/         # 🐍 Клиент: SDK Черепашки для школьников
├── workspace_2_luanti_mod/         # 🎮 Сервер: Движок симуляции и физики на Lua
├── workspace_3_web_gateway/        # 🌐 Инфра: Wasm-витрина, Nginx и WebSocket-мост
└── workspace_4_educator_layer/     # 📚 Контент: Учебные задачи и инструменты учителя
```

### Обзор рабочих пространств (Workspaces)

#### 1. `workspace_0_shared_contracts` (Священный Грааль)
* **Роль:** Единственный источник истины для сетевого протокола. Не содержит исполняемого кода — только машиночитаемые спецификации (JSON Schemas, порты, коды ошибок).
* **Принцип:** Ни один клиент или сервер не может в одностороннем порядке изменить формат пакетов. Изменения вносятся только здесь архитекторами.
* **Симлинки:** Папка спецификаций из этого модуля монтируется в остальные 4 модуля как **Read-Only каталог `shared_contracts/`**.

#### 2. `workspace_1_python_sdk` (Студенческий узел)
* **Стек:** Чистый Python 3.10+ (Standard Library).
* **Инварианты:** Строгий **Zero-Dependency** (запрет на `pip install`), чтобы код запускался на любом школьном ПК из коробки. Виртуальный сдвиг координат (ученик работает в `[-15..15]`, сеть передает `[0..31]`), пошаговая анимация (Atomic Stepping) и мгновенные локализованные ошибки (Fail-Fast).

#### 3. `workspace_2_luanti_mod` (Узел симуляции)
* **Стек:** Lua 5.1 / LuaJIT под управлением Luanti Server 5.8+.
* **Инварианты:** Абсолютно неблокирующий сокет (`settimeout(0)`), защита очередей (Time Slicing для `bulk_set_nodes`), In-Memory откат постройки без обращений к диску и невидимые барьеры от лавы. Здесь же живет подсистема «Магнитофона» (Record & Replay).

#### 4. `workspace_3_web_gateway` (Шлюз витрины)
* **Стек:** Docker Compose, Nginx (Alpine), Websockify, Vanilla JS (ES6+).
* **Инварианты:** Никаких тяжелых фреймворков (React/Vue). Только чистый JS-бутстраппер, который парсит URL `?plot=12`, генерирует никнейм и инжектит его в аргументы Wasm-модуля. Агрессивное кэширование 15-мегабайтных бинарников Wasm в Nginx.

#### 5. `workspace_4_educator_layer` (Педагогический узел)
* **Стек:** Учебные Python-скрипты на базе SDK.
* **Инварианты:** Жесткое визуальное зонирование файлов (`# --- НАЧАЛО КОДА УЧЕНИКА ---`), дидактическая спираль от простых линий к сенсорам лабиринта, многоязычность (`ru/`, `en/`) без перевода синтаксиса Python и класс `AdminBuilder` для мгновенной генерации уровней.

### Триада управления в каждом Workspace

Каждый из 5 модулей автономен и оформлен как независимый репозиторий. В корне каждого модуля лежит стандартизированная триада файлов:

1. **`PROJECT.md` (Паспорт: What & Why):** Объясняет агенту высокоуровневый смысл модуля, его аудиторию и ограничения, удерживая ИИ от архитектурных галлюцинаций.
2. **`AGENTS.md` (Конституция: How & Rules):** Набор жестких инструкций (Standing Instructions): разрешенные команды терминала, запуск линтеров (`unittest`, `luacheck`), запреты на внешние пакеты (Red Lines) и критерии готовности (Definition of Done).
3. **`llms.txt` (Индекс контекста):** Структурированная карта спецификаций в формате AI Sitemap. Указывает агенту точный порядок чтения графа зависимостей (`DAG`), экономя до 90% токенов при первичном анализе.

## 🗺️ Часть 4. Дорожная Карта и Регламент Разработки (Roadmap & SDD)

### Эволюционная стратегия: От MVP к Мультивселенной

Проект развивается итеративно. Текущий фокус — **Stage 1 (MVP)**. При этом сетевые контракты и структуры данных уже спроектированы так, чтобы будущие фазы не потребовали переписывания клиентского SDK или смены протокола.

```text
  [ Stage 1: MVP ] ──────────────► [ Stage 2: Economy ] ──────────────► [ Stage 3: Web3 ] ──────────────► [ Stage 4: Federation ]
  - Локальный Python               - Расход угля/ресурсов                - Распределенные вычисления       - P2P-сеть серверов
  - TCP-сокеты :4711               - SaaS-аренда скриптов                - Воркеры (майнинг мощностей)     - Порталы выпускников
  - Wasm-витрина :8080             - Доска игровых заказов               - Waves L1 + Passkeys/WebAuthn    - Выход в IoT (ESP32)
  - In-Memory откат                - Локальная база счетов               - Смарт-контракты Ride            - Роботы на ковре
```

### Зарезервированные архитектурные закладки (Extension Hooks)

В сетевых спецификациях `shared_contracts/` зафиксированы поля, которые в MVP работают как заглушки, но активируются на следующих этапах:

| Поле в протоколе | Текущее поведение (MVP) | Поведение в будущем (Stages 2–4) |
| :--- | :--- | :--- |
| `meta.role` | Всегда `"owner"` (хозяин участка). | `"worker"` — ПК ученика выполняет тяжелые фоновые расчеты для всей сети (майнинг). |
| `meta.host_id` | Статическая строка / телеметрия. | Уникальный криптографический ID узла в P2P-федерации (Stage 4). |
| `quota.cost` | Всегда `0` (бесплатные действия). | Списание топлива/угля за каждый шаг бота при переходе в режим выживания (Stage 2). |
| `quota.reward` | Всегда `0`. | Начисление токенов ученику за предоставление вычислительных мощностей своего ПК (Stage 3). |
| `voxel_bot:goal_node` | Выводит поздравительный чат-триггер. | Оракул для автоматического исполнения смарт-контракта сделки (Stage 3). |

### Регламент Spec-Driven Development (Инструкция для Архитекторов)

В этом репозитории действует закон: **Люди пишут спецификации, ИИ-агенты пишут код**. Прямое редактирование кода руками человека («vibe-coding») считается архитектурным долгом.

Если вам нужно добавить новую фичу или изменить поведение системы, следуйте строгому пайплайну:

1. **Фаза Specify (Контракты):**
   ЕСЛИ меняется сетевое взаимодействие, откройте `workspace_0_shared_contracts/specs/` и внесите изменения в Markdown-спецификацию (соблюдая EARS-нотацию и обратную совместимость).
2. **Фаза Sync (Синхронизация):**
   Запустите скрипт обновления симлинков, чтобы измененные контракты проросли в дочерние рабочие пространства (`workspace_1` .. `workspace_4`).
3. **Фаза Dispatch (Запуск Агентов):**
   Откройте нужный Workspace в среде Antigravity (или передайте контекст кодинг-агенту). Агент автоматически считает `AGENTS.md`, прочтет `PROJECT.md`, пройдет по графу `llms.txt` и реализует код строго по контракту.
4. **Фаза Verify (Верификация):**
   Запустите валидационные скрипты: тесты SDK через `python -m unittest`, линтинг мода через `luacheck`, проверку Docker через `docker compose config`. Код мержится только при коде возврата `0`.

### Быстрый старт для инженеров (Quick Start)

Чтобы поднять локальный полигон для ручной проверки системы:

```bash
# 1. Клонирование репозитория
git clone https://github.com/your-org/voxel_metaverse_project.git
cd voxel_metaverse_project

# 2. Запуск серверного контура (Luanti Server + Websockify + Nginx Gateway)

cd ../../workspace_1_python_sdk

# 4. Проверка веб-витрины
# Откройте в браузере: http://localhost:8080/?plot=1
```
