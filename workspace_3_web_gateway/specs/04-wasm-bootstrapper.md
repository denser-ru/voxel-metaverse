# ws3-04-wasm-bootstrapper: Логика Бесшовного Входа и Инициализация Wasm

> **ABSTRACT:** Спецификация определяет поведение клиентского фронтенд-скрипта (`bootstrapper.js`). Документ задает правила извлечения параметров маршрутизации из URL браузера, генерации временных учетных данных Гостя и инжектирования этих данных в конфигурацию движка WebAssembly (Emscripten) для пропуска Главного Меню.

## 1. URL Parameter Extraction (Парсинг маршрута)

КОГДА HTML-страница веб-шлюза загружается в браузере, бутстраппер `SHALL` извлечь параметры инициализации из адресной строки (`window.location.search`).

* Скрипт `SHALL` искать параметр `plot` (номер Участка).
  * ЕСЛИ параметр отсутствует или не является положительным целым числом, скрипт `SHALL` использовать значение по умолчанию (`[Reference Implementation: 1]`).
* Скрипт `SHALL` искать параметр `pin` (опциональный хэш доступа, если потребуется передача полномочий через ссылку).

## 2. Guest Identity Generation (Генерация эфемерной личности)

Для обеспечения совместимости с хуком авторизации на стороне сервера, бутстраппер `SHALL` автоматически сгенерировать уникальный никнейм Зрителя.

* Сгенерированный никнейм `SHALL` строго соответствовать паттерну: `Guest_P<PLOT_ID>_<RANDOM_HASH>`.
* `<PLOT_ID>` `SHALL` быть заменен на извлеченный номер участка.
* `<RANDOM_HASH>` `SHALL` генерироваться локально в браузере как случайная алфавитно-цифровая строка длиной не менее 4 символов (например, `A8B2`).
* Пароль пользователя `SHALL` генерироваться как пустая строка или случайный токен (Зрители не проходят криптографическую аутентификацию).

## 3. Emscripten Argument Injection (Пропуск Главного Меню)

Движок Luanti, скомпилированный под WebAssembly через Emscripten, принимает аргументы командной строки через глобальный объект `Module.arguments`. Бутстраппер `SHALL` сконфигурировать этот объект до загрузки бинарного файла движка.

* Бутстраппер `SHALL` передать массив аргументов, который заставит движок немедленно подключиться к серверу в обход графического меню (`GUI Main Menu`).
* Обязательные аргументы `SHALL` включать:
  * Флаг `--go` (немедленный старт).
  * Флаг `--name` со значением сгенерированного никнейма (из Раздела 2).
  * Флаг `--address` со значением адреса прокси-моста WebSocket (`[Reference Implementation: wss://<domain.com>/ws/]`). Указание протокола `ws://` или `wss://` `SHALL` динамически определяться в зависимости от текущего протокола страницы (`window.location.protocol`).
  * Флаг `--port` (если требуется специфический порт WebSocket-маршрутизатора).

## 4. Seamless Wasm Bootstrapping (Запуск движка)

После того как глобальный объект `Module` сконфигурирован, скрипт `SHALL` инициировать загрузку основного `.js` файла, сгенерированного компилятором Emscripten (glue code).

* КОГДА скрипт добавляет тег `<script>` с загрузчиком движка в DOM, загрузчик автоматически подхватит подготовленный объект `Module` с инжектированными аргументами.
* Бутстраппер `SHALL` перехватывать системные вызовы вывода (stdout/stderr) объекта `Module` для логирования процесса загрузки и отображения прогресс-бара (`setStatus()`) в пользовательском интерфейсе.
