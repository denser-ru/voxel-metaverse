# ws3-01-docker-topology: Оркестрация Контейнеров и Сетевая Изоляция

> **ABSTRACT:** Документ определяет топологию микросервисов среды развертывания. Спецификация задает контракты для файла `docker-compose.yml`, описывая виртуальные сети, маршрутизацию портов и изоляцию внутренних служб (Zero-Trust Network Architecture).

## 1. Container Orchestration Contract (Состав сервисов)

Оркестрация инфраструктуры `SHALL` описываться единым декларативным манифестом (`[Reference Implementation: docker-compose.yml]`).
Система `SHALL` инициализировать следующие логические сервисы:

* `luanti_server`: Контейнер `[[Server Node]]` (игровой движок).
* `websockify_bridge`: Контейнер транслятора протоколов (WebSocket -> UDP).
* `nginx_gateway`: Контейнер веб-шлюза (раздача статики и обратный прокси).

## 2. Network Isolation (Внутренняя сеть)

Для предотвращения несанкционированного доступа к внутренним компонентам, оркестратор `SHALL` реализовать сетевую изоляцию.

* В манифесте `SHALL` быть определена кастомная виртуальная сеть типа bridge (например, `voxel_net`).
* Все вышеперечисленные сервисы `SHALL` быть подключены исключительно к этой внутренней сети.
* Сервисы `SHALL` разрешать IP-адреса друг друга исключительно через встроенный DNS оркестратора по именам контейнеров. Использование жестко заданных IP-адресов (Hardcoded IPs) во внутренних конфигурациях `SHALL NOT` допускаться.

## 3. Port Mapping Policy (Маршрутизация портов)

Экспонирование портов (Publishing Ports) на хост-машину `SHALL` строго следовать политике минимально необходимых привилегий.

### 3.1. Public Ports (Внешний доступ)
Оркестратор `SHALL` пробросить "наружу" (на хост) только два порта:
* **Порт `4711` (TCP) сервиса `luanti_server`:** Для обеспечения прямого подключения `[[Client Node]]` (ученических Python-скриптов) к подсистеме API-шлюза.
* **Порт `8080` (TCP) сервиса `nginx_gateway`:** Для обеспечения доступа Гостей (браузеров) к Wasm-клиенту и проксированному WebSocket-трафику.

### 3.2. Isolated Ports (Изолированные порты)
Следующие порты `SHALL NOT` пробрасываться на хост-машину и `SHALL` быть доступны только внутри виртуальной сети `voxel_net`:
* **Порт `30000` (UDP) сервиса `luanti_server`:** Нативный игровой порт. К нему `SHALL` иметь доступ ИСКЛЮЧИТЕЛЬНО сервис `websockify_bridge`.
* **Внутренний порт сервиса `websockify_bridge` (например, `8081` TCP):** К нему `SHALL` иметь доступ ИСКЛЮЧИТЕЛЬНО сервис `nginx_gateway` для выполнения директивы `proxy_pass`.

## 4. Volume Mounts & Immutability (Тома и Неизменяемость)

Контейнеры шлюза `SHALL` проектироваться по принципу неизменяемой инфраструктуры (Immutable Infrastructure).

* Контейнер `nginx_gateway` `SHALL` монтировать директории `./html/` и `./deploy/nginx/` исключительно в режиме "Только для чтения" (Read-Only, `:ro`).
* Контейнеры шлюза `SHALL NOT` хранить какое-либо персистентное состояние внутри своих файловых систем. 
* Любые журналы (Logs) `SHALL` маршрутизироваться в `stdout`/`stderr` для автоматического сбора демоном оркестратора, а не писаться в локальные файлы контейнера.
