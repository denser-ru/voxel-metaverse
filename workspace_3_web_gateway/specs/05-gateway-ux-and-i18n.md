# ws3-05-gateway-ux-and-i18n: Пользовательский Интерфейс Шлюза и Локализация

> **ABSTRACT:** Спецификация определяет требования к Frontend-интерфейсу страницы входа (`index.html`). Документ регламентирует поведение загрузочного экрана (Loading Screen), автоопределение языка браузера для перевода интерфейса (i18n) и безопасную обработку аппаратных или сетевых ошибок до запуска Wasm-движка.

## 1. Loading Screen UX (Пользовательский опыт при загрузке)

Загрузка бинарных файлов WebAssembly и инициализация графического контекста занимают время. Интерфейс `SHALL` сглаживать этот процесс для конечного пользователя.

* КОГДА страница загружается, HTML `SHALL` отображать оверлей загрузки (Loading Overlay) с графическим индикатором прогресса (Progress Bar) и статусной строкой.
* Фронтенд-скрипт `SHALL` перехватывать вызовы функции `setStatus(text)` от объекта `Module` (Emscripten) и обновлять статусную строку в UI.
* Элемент `<canvas>`, в котором рендерится 3D-мир, `SHALL` оставаться скрытым (или находиться под оверлеем) до тех пор, пока движок не сообщит о полной готовности.
* Интерфейс `SHALL NOT` выводить сырой консольный вывод (stdout/stderr) движка на видимую часть экрана, оставляя его исключительно в `console.log` браузера для отладки.

## 2. Browser-native i18n (Автоматическая локализация)

Для соблюдения принципов бесшовного входа глобальной аудитории, UI-шлюз `SHALL` локализовывать свои тексты без запроса у пользователя.

* Фронтенд `SHALL` определять предпочитаемый язык пользователя, используя встроенный API `navigator.language` (или `navigator.languages[0]`).
* Логика i18n `SHALL` извлекать базовый код языка (ISO 639-1, например, `"ru"`, `"en"`, `"es"`) из значения `navigator.language`.
* Все текстовые узлы (Text Nodes) в DOM (статусы загрузки, сообщения об ошибках) `SHALL` заполняться из локального JS-словаря на основе определенного языка.
* ЕСЛИ язык браузера отсутствует в словаре, UI `SHALL` использовать фоллбэк (Fallback) на английский язык (`"en"`).

## 3. Graceful Error Handling (Обработка критических ошибок)

Веб-шлюз `SHALL` уметь распознавать ситуации, когда запуск 3D-мира невозможен, и информировать пользователя на понятном языке.

* **Hardware Compatibility (Совместимость WebGL):**
  * Перед попыткой загрузить `.wasm`, скрипт `SHALL` проверить поддержку WebGL в браузере (`[Reference Implementation: проверка создания контекста canvas.getContext("webgl2")]`).
  * ЕСЛИ WebGL не поддерживается, скрипт `SHALL` прервать загрузку и вывести локализованное сообщение (например, *"Ваш браузер или устройство не поддерживает 3D-графику"*).
* **Network & Connection Drop (Сетевые сбои):**
  * КОГДА WebSocket-прокси (из `[[ws3-02-websockify-bridge]]`) недоступен ИЛИ соединение обрывается до загрузки мира, UI `SHALL` скрыть Canvas и отобразить плашку с ошибкой соединения.
  * Текст ошибки `SHALL NOT` содержать пугающих системных трейсов (stack traces). Он `SHALL` быть дружелюбным (например, *"Сервер временно недоступен или обновляется. Попробуйте обновить страницу позже."*).
