# ws2-01-engine-lifecycle: Жизненный цикл мода и интеграция с Движком

> **ABSTRACT:** Спецификация описывает точку входа серверного плагина (`init.lua`). Документ устанавливает контракты взаимодействия с подсистемой безопасности движка Luanti, порядок загрузки зависимостей и правила внедрения в главный игровой цикл без нарушения инварианта Zero-Lag.

## 1. Security Environment Negotiation (Запрос небезопасного окружения)

Движок Luanti по умолчанию изолирует моды (Sandboxing), запрещая им доступ к системным библиотекам ОС (включая работу с сокетами). Точка входа мода `SHALL` явно запрашивать расширенные права.

* КОГДА мод загружается движком, он `SHALL` вызвать запрос на получение небезопасного окружения (`[Reference Implementation: minetest.request_insecure_environment()]`).
* ЕСЛИ окружение не предоставлено (мод не добавлен в список `secure.trusted_mods` конфигурации сервера), мод `SHALL` вывести критическую ошибку в лог сервера и принудительно прервать загрузку (`[Reference Implementation: error()]`), так как дальнейшая работа без TCP-сокетов невозможна.
* Полученное небезопасное окружение `SHALL` использоваться ИСКЛЮЧИТЕЛЬНО для загрузки библиотеки сокетов. Мод `SHALL NOT` использовать эти права для выполнения команд ОС или доступа к файловой системе вне выделенных хранилищ.

## 2. Mod Bootstrapping (Порядок инициализации)

Глобальное пространство имен мода `SHALL` быть строго изолировано. Мод `SHALL` экспортировать ровно одну глобальную таблицу (например, `voxel_bot`).
Инициализация подсистем в `init.lua` `SHALL` происходить в строгом порядке для избежания состояния гонки (Race Conditions):

1. **Storage & Config:** Инициализация `Mod Storage` для персистентного хранения.
2. **Geometry & Plot Manager:** Регистрация узлов (nodes), барьеров и логики вычисления координат (согласно `[[ws2-03-plot-geometry]]`).
3. **Entities:** Регистрация сущности Черепашки (согласно `[[ws2-04-entity-and-physics]]`).
4. **Queues & State Machines:** Инициализация буферов команд и логики витрины.
5. **Network Ingress:** Поднятие TCP-сервера и начало прослушивания порта (согласно `[[ws2-02-network-ingress]]`).

## 3. Main Loop Integration (Интеграция в Главный Цикл)

Вся асинхронная работа (сеть, движение ботов) `SHALL` выполняться в синхронизации с тактовым генератором сервера (Tick Rate).

* Мод `SHALL` зарегистрировать глобальный хук обновления (`[Reference Implementation: minetest.register_globalstep(function(dtime))]`).
* На каждом тике `globalstep`, мод `SHALL` последовательно вызывать:
  1. `network_ingress.poll()`: Неблокирующее чтение входящих сетевых пакетов.
  2. `command_queue.process(dtime)`: Выполнение дозированного объема команд из очередей участков.
  3. `demo_engine.tick(dtime)`: Обновление таймеров откатов и анимаций "пленки" для зрителей.
* **Zero-Lag Constraint:** Суммарное время выполнения всех шагов внутри хука `globalstep` `SHALL NOT` приводить к блокировке движка. Все операции ввода-вывода внутри хука `SHALL` быть строго асинхронными/неблокирующими.

## 4. Graceful Shutdown (Корректное завершение)

* КОГДА сервер получает сигнал на остановку (Shutdown), мод `SHALL` перехватить событие выключения (`[Reference Implementation: minetest.register_on_shutdown]`).
* В обработчике выключения мод `SHALL`:
  1. Принудительно закрыть слушающий TCP-сокет и все активные клиентские соединения.
  2. Сбросить (flush) все критические изменения из оперативной памяти (например, новые PIN-коды участков) в персистентное `Mod Storage`.
