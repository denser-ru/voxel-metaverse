# ws2-07-auth-and-guests: Аутентификация и Контроль Прав Зрителей

> **ABSTRACT:** Спецификация определяет подсистему `guest_auth`. Документ регламентирует механизм Stateless-авторизации TCP-клиентов (Создателей) через проверку хэшей PIN-кодов, а также правила перехвата игровых подключений для принудительного перевода веб-клиентов (Зрителей) в безопасный режим Spectator.

## 1. Creator Authentication & Persistent Storage (Авторизация TCP-клиента)

КОГДА `[[Client Node]]` отправляет команду `init_bot` через TCP-шлюз, подсистема `SHALL` валидировать параметр `meta.pin_hash` перед привязкой сессии к Участку.

* **Хранилище:** Подсистема `SHALL` использовать `Mod Storage` (`[Reference Implementation: minetest.get_mod_storage()]`) как персистентное Key-Value хранилище для пар `plot_id -> pin_hash`. Это гарантирует сохранение доступов при рестарте сервера.
* **Trust-on-First-Use (TOFU):**
  * ЕСЛИ `plot_id` запрашивается впервые (отсутствует в хранилище), подсистема `SHALL` автоматически зарегистрировать участок, сохранить присланный `pin_hash` как эталонный и разрешить доступ.
* **Validation (Валидация):**
  * ЕСЛИ `plot_id` уже существует в хранилище, подсистема `SHALL` сравнить присланный `pin_hash` с эталонным.
  * ЕСЛИ хэши не совпадают, подсистема `SHALL` отклонить запрос, вернув `error.code = "INVALID_PIN"`, и разорвать TCP-соединение.

## 2. Guest Login Hook (Перехват входа Зрителей)

Зрители (Guests) подключаются через `[[Web Gateway]]` (Wasm-клиент) напрямую к движку Luanti. Подсистема `SHALL` перехватывать их вход для маршрутизации.

* Подсистема `SHALL` зарегистрировать обработчик входа игрока (`[Reference Implementation: minetest.register_on_joinplayer(function(player))]`).
* Внутри обработчика подсистема `SHALL` анализировать никнейм игрока.
* КОГДА никнейм совпадает с регулярным выражением `^Guest_P(%d+)_[a-zA-Z0-9]+$` (например, `Guest_P12_A8B2`):
  * Подсистема `SHALL` извлечь номер Участка (в данном примере `12`) из никнейма.
  * Подсистема `SHALL` немедленно применить профиль Spectator Mode (см. Раздел 3) и телепортировать игрока на Гостевую Зону Участка.

## 3. Spectator Privilege Enforcement (Профиль Зрителя)

Для предотвращения вандализма (гриферства) и вмешательства в алгоритмы учеников, Гости `SHALL` быть аппаратно ограничены в правах на уровне движка.

* **Revocation (Лишение прав):** Подсистема `SHALL` удалить у Гостя привилегию `interact`. Это нативно блокирует способность ломать блоки, устанавливать блоки, атаковать сущности и использовать предметы инвентаря.
* **Granting (Выдача прав):** Подсистема `SHALL` выдать Гостю привилегии `fly` (полет) и `fast` (ускорение), чтобы зритель мог свободно облетать и рассматривать 3D-постройки с любого ракурса.
* **Teleportation (Маршрутизация):** 
  * Подсистема `SHALL` запросить координаты гостевого пьедестала $X_{guest}, Y_{guest}, Z_{guest}$ у `[[ws2-03-plot-geometry]]` для целевого Участка.
  * Игрок `SHALL` быть телепортирован в эту точку (`player:set_pos()`), а вектор его взгляда (Look Pitch/Yaw) `SHALL` быть принудительно направлен в центр рабочей зоны Участка.
