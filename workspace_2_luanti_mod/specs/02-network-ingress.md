# ws2-02-network-ingress: Сетевой Шлюз и Неблокирующий I/O

> **ABSTRACT:** Документ описывает подсистему `network_ingress`, отвечающую за прием TCP-соединений, безопасную десериализацию NDJSON и маршрутизацию команд. Контракт жестко регламентирует механизмы защиты от блокировки главного потока движка (Non-Blocking I/O) и переполнения памяти (Buffer Bloat).

## 1. Non-Blocking Socket Initialization (Инициализация сокета)

* В процессе загрузки мода подсистема `network_ingress` `SHALL` инициализировать слушающий TCP-сервер (`[Reference Implementation: socket.bind("*", 4711)]`).
* Серверный сокет `SHALL` быть немедленно переведен в неблокирующий режим (`[Reference Implementation: server:settimeout(0)]`).
* На каждом тике `globalstep`, подсистема `SHALL` вызывать `server:accept()`. 
  * ЕСЛИ поступает новое соединение, клиентский сокет также `SHALL` переводиться в неблокирующий режим `settimeout(0)`.
  * Клиентский сокет добавляется во внутренний пул активных соединений.

## 2. Session Lifecycle Management (Управление сессиями)

Подсистема `SHALL` связывать каждое физическое TCP-соединение с конкретным Участком (`plot_id`), чтобы гарантировать изоляцию.

* КОГДА клиент присылает команду `init_bot`, подсистема `SHALL` авторизовать клиента (согласно `[[ws2-07-auth-and-guests]]`).
* В случае успешной авторизации, TCP-соединение "привязывается" к `plot_id`. 
* **Connection Drop (Обрыв связи):** ЕСЛИ операция `receive` возвращает ошибку `closed` (или сокет разорван по таймауту), подсистема `SHALL`:
  1. Удалить клиентский сокет из пула.
  2. Вызвать метод очистки очередей в `[[ws2-05-safety-guardrails]]`, чтобы мгновенно остановить алгоритмы, исполнявшиеся для этого `plot_id`.

## 3. NDJSON Deserialization & Safety (Безопасный парсинг)

Luanti падает (Crash), если функция `minetest.parse_json` получает невалидную строку. Подсистема `SHALL` защищать сервер от некорректных данных (Fault Tolerance).

* Подсистема `SHALL` вычитывать данные из клиентских сокетов до разделителя `\n`.
* КОГДА строка прочитана, вызов JSON-парсера `SHALL` быть обернут в защищенный вызов (`[Reference Implementation: pcall(minetest.parse_json, raw_string)]`).
* ЕСЛИ парсинг завершается с ошибкой (например, клиент прислал битый JSON), подсистема `SHALL` отправить ответ с `error.code = "PROTOCOL_ERROR"` и `SHALL NOT` прерывать работу сервера.
* Валидированный JSON-объект передается в очередь команд соответствующего `plot_id`.

## 4. TCP Backpressure & Read Limits (Защита от DDoS)

Для предотвращения зависания сервера при агрессивной отправке данных клиентом (например, ученик написал цикл на 100 000 итераций без задержки), подсистема `SHALL` ограничивать объем чтения.

* В рамках одного вызова `network_ingress.poll()` (за один серверный тик), подсистема `SHALL` читать **не более `MAX_READS_PER_TICK` строк** (по умолчанию `100`) от одного активного TCP-клиента.
* ЕСЛИ лимит достигнут, подсистема `SHALL` прервать цикл чтения для этого клиента до следующего серверного тика.
* *Следствие:* Непрочитанные байты останутся в сетевом буфере операционной системы. Когда буфер ОС переполнится, на стороне `[[Client Node]]` автоматически сработает блокировка TCP-окна (TCP Window Full), и Питон-скрипт ученика будет естественно "приторможен" без падения сервера.

## 5. Asynchronous Responses (Асинхронная отправка)

* КОГДА подсистема или бизнес-логика мода формирует ответ для клиента, она `SHALL` сериализовать его в JSON, добавить суффикс `\n` и отправить через `client:send()`.
* Подсистема `SHALL` перехватывать ошибки `send()` (например, клиент отключился до получения ответа) и корректно закрывать сессию без падения сервера.
