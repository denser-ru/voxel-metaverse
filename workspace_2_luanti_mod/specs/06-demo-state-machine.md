# ws2-06-demo-state-machine: Конечный Автомат Витрины и Откат Состояния

> **ABSTRACT:** Спецификация определяет подсистему `demo_engine`. Документ регламентирует жизненный цикл интерактивной витрины Участка, алгоритм записи действий робота (Record & Replay) и бессерверный откат изменений блоков в оперативной памяти (In-Memory Delta Rollback) без использования дискового I/O.

## 1. Showcase State Machine (Конечный Автомат)

Каждый Участок (`plot_id`) `SHALL` иметь независимое состояние витрины. Подсистема `SHALL` оперировать следующими состояниями:
* **`IDLE`**: Участок простаивает, ожидает команд или действий гостя.
* **`RECORDING`**: Активна запись команд в "пленку" (Tape).
* **`PLAYING_DEMO`**: Выполняется автоматическое воспроизведение сохраненной "пленки" для зрителей.
* **`RESETTING`**: Происходит процедура возврата измененных блоков к исходному состоянию (Откат).

## 2. Record & Replay Mechanism (Запись и Воспроизведение)

Для обеспечения доступности витрины в режиме 24/7 (когда `[[Client Node]]` отключен), подсистема `SHALL` реализовать механизм записи.

### 2.1. Режим записи (Record)
* КОГДА подсистема получает сетевую команду `start_recording` (из `[[03-commands-registry]]`), состояние Участка `SHALL` переключиться в `RECORDING`. Текущая "пленка" (массив команд в памяти) очищается.
* ПОКА Участок находится в состоянии `RECORDING`, любые успешно выполненные команды, изменяющие состояние мира (например, `step` с `pen_down == true`, `set_node`), `SHALL` добавляться в массив "пленки".
* КОГДА поступает команда `save_tape`, подсистема `SHALL` сериализовать массив "пленки" в JSON и сохранить его в персистентное хранилище `Mod Storage` (согласно `[[ws2-00-domain-vision]]`). Состояние переключается в `IDLE`.

### 2.2. Режим воспроизведения (Replay)
* КОГДА инициируется показ демо (см. Раздел 4), подсистема `SHALL` извлечь "пленку" из `Mod Storage`.
* Подсистема `SHALL` переключить состояние в `PLAYING_DEMO` и начать итеративно скармливать команды из "пленки" в очередь исполнения Участка (`command_queue`), симулируя наличие клиента.
* КОГДА "пленка" заканчивается, подсистема `SHALL` запустить таймер осмотра (например, 15 секунд), после чего перевести Участок в состояние `RESETTING`.

## 3. In-Memory Delta Rollback (Откат в оперативной памяти)

Для соблюдения инварианта Zero-Lag, подсистема `SHALL NOT` использовать синхронные вызовы `minetest.create_schematic()` или сохранение на жесткий диск. 

* КОГДА начинается любая активность по модификации Участка (через сеть или Replay), подсистема `SHALL` инициализировать в оперативной памяти пустую Lua-таблицу `modified_blocks = {}`.
* Перед каждым вызовом `minetest.set_node`, подсистема `SHALL` прочитать текущий (старый) блок по заданным координатам. ЕСЛИ этих координат еще нет в таблице `modified_blocks`, подсистема `SHALL` записать туда оригинальное состояние блока (название материала).
* КОГДА Участок переходит в состояние `RESETTING` (или при получении команды `wipe`), подсистема `SHALL` итерироваться по ключам таблицы `modified_blocks` и восстанавливать оригинальные узлы.
* Процесс восстановления `SHALL` подчиняться правилу Time Slicing из `[[ws2-05-safety-guardrails]]` (не более `MAX_BLOCKS_PER_SLICE` за тик), чтобы избежать фризов сервера при очистке огромных построек. После очистки состояние возвращается в `IDLE`.

## 4. Guest Interaction (Взаимодействие с Гостем)

На каждом Участке установлен интерактивный триггер — узел `voxel_bot:demo_button`.

* КОГДА любой игрок (Гость) нажимает (right-click / punch) на кнопку, подсистема `SHALL` выполнить проверку состояний:
  * ЕСЛИ состояние `PLAYING_DEMO` ИЛИ `RESETTING`, подсистема `SHALL` проигнорировать нажатие (и опционально вывести гостю в чат сообщение об ожидании).
  * ЕСЛИ состояние `IDLE` И `[[Client Node]]` подключен к Участку по TCP: подсистема `SHALL` отправить в TCP-сокет событие `"events": ["DEMO_STARTED"]`, позволяя клиентскому скрипту выйти из блокировки `wait_for_guest_trigger()`.
  * ЕСЛИ состояние `IDLE` И TCP-клиент НЕ подключен (Офлайн-режим): подсистема `SHALL` проверить наличие сохраненной "пленки" в `Mod Storage`. ЕСЛИ "пленка" есть — запустить Режим Воспроизведения (Replay). ЕСЛИ нет — вывести гостю уведомление об отсутствии данных.
