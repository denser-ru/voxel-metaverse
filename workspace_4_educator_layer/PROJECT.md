# PROJECT: Educator Layer & Content Engine (Движок Учебного Контента)

> **ABSTRACT:** Данный файл описывает бизнес-смысл, целевую аудиторию и образовательную философию модуля создания уроков. ИИ-агенты `SHALL` использовать этот документ для калибровки своего стиля написания кода и комментариев, отдавая абсолютный приоритет педагогической ясности (Pedagogy over Optimization).

## 1. System Passport (Бизнес-миссия: "Что и Зачем")

**Продукт:** Набор дидактически выверенных учебных скриптов (задач), шаблонов уроков и административных инструментов для преподавателя.
**Целевая аудитория (Конечный пользователь):** Школьники 11–14 лет (Ученики) и их Преподаватели (или ИИ-менторы).

**Глобальная цель (The Why):** 
Превратить технический `[[Python SDK]]` в пошаговое образовательное путешествие. Ученик, открывающий файл с уроком, `SHALL NOT` испытывать когнитивного перегруза от обилия системного кода. Урок должен мягко вести его по "Дидактической спирали": от простейших прямых линий к пониманию того, зачем нужны циклы `for`, переменные и условные операторы `if`. Успех этого модуля измеряется тем, насколько редко ученик ломает инфраструктурную часть скрипта, пытаясь решить саму задачу.

## 2. Architectural Boundaries (Границы Архитектуры)

Рабочее пространство `educator-layer` является исключительно Потребителем (Consumer) клиентского SDK.

* **Consumer Role (Роль пользователя):** Агенты в этом рабочем пространстве `SHALL NOT` модифицировать ядро библиотеки `voxel_turtle.py`. Их задача — импортировать библиотеку и писать скрипты *поверх* нее.
* **Code Zoning (Изоляция сложности):** Учебный скрипт `SHALL` состоять из двух жестко разделенных миров. "Зона Преподавателя" (импорты, настройка мира, генерация лабиринтов) `SHALL` быть отделена от "Зоны Ученика" (пустое место с комментариями-подсказками, где ребенок пишет свой код).
* **Pedagogy > Optimization (Понятность важнее оптимизации):** В учебных примерах и подсказках `SHALL NOT` использоваться продвинутые конструкции Python (например, list comprehensions, лямбды, генераторы), если они не являются темой урока. Код `SHALL` быть максимально явным, императивным и читаемым для новичка.
* **Multilingual from Day 1 (Мультиязычность):** Весь контент (уроки) `SHALL` поддерживать i18n на уровне файловой системы (разные директории для `en/` и `ru/`), но синтаксис Python и API SDK `SHALL` всегда оставаться на английском.

## 3. Educator Domain Glossary (Глоссарий Методиста)

* **Setup Zone (Зона Преподавателя):** Верхняя и нижняя части `.py` файла урока. Отвечает за инициализацию бота, установку скорости, очистку участка и проверку условий победы. Ученик не должен трогать этот код.
* **Student Zone (Зона Ученика):** Свободная область внутри файла, ограниченная комментариями `# --- НАЧАЛО КОДА УЧЕНИКА ---`. Единственное место, где ученик пишет код.
* **Didactic Spiral (Дидактическая спираль):** Принцип усложнения. Каждый урок вводит строго одну новую сущность (например, только циклы, или только сенсоры).
* **AdminBuilder:** Расширенный класс SDK для учителя. Позволяет мгновенно загрузить сложный лабиринт на Участок перед тем, как ученик начнет его проходить. Дети об этом классе не знают.
