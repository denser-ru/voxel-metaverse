# ws4-01-task-template-contract: Контракт Структуры Учебного Файла

> **ABSTRACT:** Спецификация определяет физическую и логическую структуру файлов учебных заданий. Документ вводит жесткое разделение файла на неизменяемую инфраструктурную зону (Зона Преподавателя) и рабочую область (Зона Ученика), гарантируя, что ошибки пользователя не нарушат сетевую инициализацию бота.

## 1. Lesson File Architecture (Архитектура файла урока)

Каждый скрипт-урок (Lesson Script) `SHALL` представлять собой автономный исполняемый файл. Архитектура файла `SHALL` строго состоять из трех последовательных секций:
1. **Setup Zone** (Инициализация и настройка окружения).
2. **Student Zone** (Изолированная песочница для решения задачи).
3. **Validation Zone** (Проверка результатов и обратная связь).

## 2. Code Zoning Contract (Контракт Зонирования)

ИИ-агенты `SHALL` внедрять явные текстовые маркеры-границы для визуального ориентирования ученика.

### 2.1. The Setup Zone (Зона Преподавателя)
* В этой секции `SHALL` выполняться импорт класса `Turtle` из `[[Python SDK]]` и его инстанцирование.
* Секция `SHALL` содержать вызовы методов, подготавливающих площадку (например, очистка Участка через `wipe()`, установка скорости `speed()`, начальный выбор материала).
* Код в этой зоне `SHALL NOT` содержать инструкций или заданий для ученика. Он `SHALL` восприниматься как системный "черный ящик".

### 2.2. The Student Zone (Рабочая область)
* Начало и конец зоны `SHALL` быть жестко обозначены визуальными разделителями (`[Reference Implementation: # --- НАЧАЛО КОДА УЧЕНИКА ---]`).
* Внутри этой зоны `SHALL` располагаться текстовое описание текущей задачи в виде комментариев.
* Зона `SHALL` предоставлять минимальную стартовую заготовку (Boilerplate) или пустое пространство, где ученик `SHALL` написать свой алгоритм.

### 2.3. The Validation Zone (Зона проверки)
* Располагается после закрывающего маркера Зоны Ученика.
* Секция `SHALL` содержать логику оценки успешности выполнения алгоритма.
* КОГДА задача предполагает достижение цели, код `SHALL` проверять статус (`[Reference Implementation: if bot.is_goal_reached():]`) и выводить соответствующее сообщение в консоль (stdout).

## 3. Didactic Commenting Standards (Стандарты комментирования)

Поскольку целевой аудиторией являются дети 11–14 лет, ИИ-агенты `SHALL` применять специфические правила к комментариям в Зоне Ученика:

* **Simplicity (Простота):** Комментарии `SHALL` использовать короткие, утвердительные предложения. Академические термины (например, "итерирование", "инстанс") `SHALL` заменяться на понятные аналоги ("повторение", "бот").
* **Actionable TODOs (Практические шаги):** Задача `SHALL` разбиваться на микро-шаги. ЕСЛИ задача требует цикла и условия, комментарий `SHALL` содержать подсказки (`[Reference Implementation: # Шаг 1: Напиши цикл для 5 шагов. # Шаг 2: Проверь, есть ли впереди стена]`).
* **Safe Fails (Поощрение ошибок):** В комментариях `SHALL` присутствовать напоминание о том, что ошибки в консоли (красный текст) — это нормально, и их нужно читать, так как они описывают причину остановки (интеграция с политикой Fail-Fast из `[[Python SDK]]`).
