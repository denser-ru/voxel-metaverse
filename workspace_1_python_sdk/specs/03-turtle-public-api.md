# ws1-03-turtle-public-api: Публичный Интерфейс Черепашки и Управление Состоянием

> **ABSTRACT:** Документ описывает структуру главного класса `Turtle`, который импортируется учениками (`from voxel_turtle import Turtle`). Спецификация определяет инварианты внутреннего состояния, логику декомпозиции длинных шагов для плавной анимации и сигнатуры публичных методов API.

## 1. Turtle Internal State (Управление состоянием)

Класс `Turtle` `SHALL` выступать как единая точка входа. При инициализации он `SHALL` установить сетевое соединение через `[[ws1-01-network-client]]`, отправить команду `init_bot` и получить стартовые координаты.

Внутреннее состояние экземпляра `SHALL` хранить следующие приватные переменные:
* `_pos`: Кортеж `(x, y, z)` в `User Space` (инициализируется ответом от `init_bot` с инверсией координат).
* `_heading`: Целое число `0..3` (согласно `[[ws1-02-coordinate-math]]`).
* `_pen_down`: Булево значение (по умолчанию `False`).
* `_material`: Строка, текущий алиас блока (по умолчанию `"stone"`).
* `_delay`: Float, задержка в секундах между сетевыми запросами (по умолчанию `0.05`).
* `_goal_reached`: Булево значение, флаг достижения финиша (по умолчанию `False`).

**State Synchronization:** КОГДА класс `Turtle` получает ответ от сервера с полем `data.local_pos`, он `SHALL` применять обратный сдвиг (Network -> User Space) и принудительно синхронизировать свою внутреннюю переменную `_pos` с серверной правдой (Server is the Source of Truth).

## 2. Atomic Stepping & Visual Smoothness (Декомпозиция шагов)

Для обеспечения визуальной плавности постройки на стороне зрителя (Гостя), класс `Turtle` `SHALL NOT` отправлять команды мульти-блокового перемещения одним запросом.

* КОГДА ученик вызывает `forward(distance=5)`, SDK `SHALL` разбить это на цикл из 5 атомарных вызовов внутренней функции `_single_step()`.
* Внутри `_single_step()`, класс `Turtle` `SHALL`:
  1. Вычислить координаты следующего единственного шага через `[[ws1-02-coordinate-math]]`.
  2. Сформировать payload `{"action": "step", "params": {...}}`.
  3. Отправить запрос и дождаться ответа от сервера.
  4. ЕСЛИ `status == "error"`, выбросить локализованное исключение (согласно `[[ws1-04-error-and-i18n]]`).
  5. Сделать системную паузу `time.sleep(self._delay)`.
* **Управление скоростью (`speed`):** Публичный метод `speed(val: int)` `SHALL` изменять значение `_delay`. 
  * ЕСЛИ `val == 10` (или `0`), ТОГДА `_delay = 0` (максимальная скорость, без пауз).
  * ЕСЛИ `val == 1`, ТОГДА `_delay = 0.3` (очень медленно).

## 3. Movement & Drawing API (API Движения и Рисования)

Сигнатуры методов `SHALL` быть строго совместимы со стандартным модулем Python `turtle`.

### 3.1. Базовая 2D-кинематика
* `forward(distance: int = 1)` / `fd`: Движение вперед по текущему `_heading`. Использует Atomic Stepping.
* `backward(distance: int = 1)` / `bk`: Движение назад. Использует Atomic Stepping с обратным вектором.
* `right(angle: int = 90)` / `rt`: Поворот вправо. Изменяет `_heading`. (Сетевой запрос не отправляется, это чисто локальное состояние).
* `left(angle: int = 90)` / `lt`: Поворот влево.

### 3.2. Воксельное 3D-расширение
* `up(distance: int = 1)`: Движение строго вверх по оси Y. Задействует Atomic Stepping.
* `down(distance: int = 1)`: Движение строго вниз по оси Y. Задействует Atomic Stepping.

### 3.3. Управление пером и материалами
* `penup()` / `up_pen()`: Устанавливает `_pen_down = False`. Блоки при движении не ставятся.
* `pendown()` / `down_pen()`: Устанавливает `_pen_down = True`. 
* `color(material_alias: str)`: Изменяет `_material`. ЕСЛИ передано недопустимое значение, сервер вернет ошибку при первом же шаге.
* `set_block(dx: int = 0, dy: int = 0, dz: int = 0)`: Установка блока со смещением относительно текущей позиции `_pos` **без перемещения бота**. Транслируется в сетевую команду `set_node`.

## 4. Sensory API & World Interaction (Сенсоры и Взаимодействие)

Для реализации алгоритмов обхода препятствий и лабиринтов, SDK `SHALL` предоставлять методы-сенсоры. Вызов этих методов инициирует синхронный сетевой запрос `get_node` или `get_llm_context` к `[[Server Node]]`.

* **`detect() -> bool`**:
  * Вычисляет координаты соседнего блока по курсу движения (на основе `_pos` и `_heading`).
  * Отправляет запрос `get_node`.
  * Возвращает `True`, ЕСЛИ блок является твердым препятствием (`is_solid == true`). Возвращает `False`, ЕСЛИ это воздух или проницаемый блок.
* **`inspect() -> dict`**:
  * Работает аналогично `detect()`, но возвращает полный словарь свойств блока (например, `{"material": "stone", "is_solid": true}`).
* **`is_goal_reached() -> bool`**:
  * Возвращает значение внутреннего флага `_goal_reached`.
  * **Event Hook:** КОГДА любой сетевой ответ от сервера содержит в массиве `events` строку `"GOAL_REACHED"`, SDK `SHALL` навсегда установить `_goal_reached = True` для текущей сессии и опционально вывести в `stdout` сообщение о победе.
* **`get_llm_context(radius: int = 5) -> dict`**:
  * Отправляет команду `get_llm_context`. Возвращает "семантическое зрение" (JSON) для передачи в нейросети.

## 5. Showcase & Session Management (Управление Витриной и Записью)

Методы данного раздела управляют жизненным циклом участка и взаимодействием с Гостями.

* **`wait_for_guest_trigger(poll_interval: float = 0.5) -> None`**:
  * `SHALL` блокировать выполнение Python-скрипта (через `time.sleep()`), циклически отправляя команду `poll_events` на сервер.
  * КОГДА ответ сервера содержит событие `"DEMO_STARTED"`, метод `SHALL` прервать цикл блокировки и вернуть управление основному коду.
* **`start_recording() -> None`**:
  * Отправляет команду `start_recording`. Сообщает серверу о необходимости начать запись всех последующих действий в "пленку" (Tape) для офлайн-витрины.
* **`save_tape() -> None`**:
  * Отправляет команду `save_tape`. Фиксирует записанную "пленку" в базе сервера.
* **`wipe() -> None`**:
  * Отправляет команду `reset_plot` с параметром `mode: "clear_all"`. `SHALL` дождаться подтверждения сервера об очистке участка.

## 6. Advanced Tooling: AdminBuilder (Инструментарий Архитектора)

Для нужд преподавателей и ИИ-Агентов, SDK `SHALL` экспортировать дополнительный класс `AdminBuilder`, наследующий всю логику `Turtle`.

* **Класс `AdminBuilder(Turtle)`**:
  * `SHALL` предоставлять метод `build_from_json(nodes: list[dict]) -> None`.
  * Метод `SHALL` принимать список словарей с относительными координатами (User Space).
  * Метод `SHALL` транслировать координаты в Network Space и упаковывать их в единую сетевую команду `bulk_set_nodes`.
  * *Примечание:* Метод `SHALL NOT` использовать Atomic Stepping и задержки `_delay`. Он отправляет весь массив за один запрос, делегируя безопасную отрисовку (Time Slicing) серверу.
