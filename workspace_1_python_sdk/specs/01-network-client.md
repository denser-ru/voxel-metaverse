# ws1-01-network-client: Спецификация Транспортного Слоя (Network Client)

> **ABSTRACT:** Документ определяет контракт реализации низкоуровневого сетевого слоя SDK (модуль `transport.py`). Описаны алгоритмы установки соединения, фрейминга сообщений (NDJSON), безопасного хэширования PIN-кодов и маппинга системных сетевых ошибок в доменные исключения.

## 1. TCP Socket Lifecycle (Жизненный цикл соединения)

Модуль `SHALL` инкапсулировать работу с сетью внутри выделенного класса (например, `TurtleTransport`).

* **Initialization:** При инициализации класс `SHALL` открыть синхронный TCP-сокет к `[[Server Node]]` (адрес и порт передаются извне, по умолчанию `localhost:4711`).
* **Timeout:** Для всех операций сокета (подключение, чтение, запись) `SHALL` быть установлен жесткий таймаут (по умолчанию `5.0` секунд).
* **Context Manager:** Класс `SHALL` реализовывать магические методы `__enter__` и `__exit__`, чтобы гарантировать корректное закрытие TCP-сокета (отправку FIN-пакета) при завершении работы или падении скрипта. КОГДА скрипт выходит из блока `with`, транспорт `SHALL` немедленно вызвать `socket.close()`.

## 2. Authentication Hashing (Хэширование PIN-кода)

Для соблюдения принципов `[[00-domain-vision]]` (Zero-Trust), `[[Client Node]]` `SHALL NOT` передавать PIN-код Участка в открытом виде.

* КОГДА пользователь инициализирует SDK с параметрами `plot_id` и `pin`, транспортный слой `SHALL` сгенерировать криптографический хэш.
* **Алгоритм хэширования:**
  * Использовать `SHA-256` (`[Reference Implementation: hashlib.sha256 в Python]`).
  * Формат входной строки (Salted Payload): строковое представление `"{plot_id}:{pin}"` (например, `"12:1234"`), закодированное в `UTF-8`.
  * Результирующий `pin_hash` `SHALL` представлять собой hex-строку (64 символа) и передаваться в поле `meta.pin_hash` каждого запроса.

## 3. NDJSON Serialization (Отправка фреймов)

КОГДА высокоуровневый код запрашивает отправку команды, транспортный слой `SHALL` выполнить следующие шаги:
1. Сформировать `dict` согласно базовой схеме запроса из `[[01-network-transport]]`.
2. Автоматически инжектить текущий `req_id` (инкрементируя внутренний счетчик сессии) и блок `meta`.
3. Сериализовать объект в JSON-строку (`[Reference Implementation: json.dumps(ensure_ascii=False, separators=(',', ':'))]`).
4. Добавить к строке символ `\n` и закодировать в байты `UTF-8`.
5. Отправить данные в сокет (`[Reference Implementation: socket.sendall()]`).

## 4. NDJSON Deserialization (Чтение фреймов и Буферизация)

Поскольку TCP является потоковым протоколом, данные могут приходить фрагментированными. Транспортный слой `SHALL` корректно обрабатывать фрагментацию.

* Чтение из сокета `SHALL` происходить в цикле, накапливая сырые байты во внутреннем буфере.
* КОГДА в буфере обнаруживается байт `\n` (`0x0A`), транспорт `SHALL` отделить завершенный фрейм, декодировать его как `UTF-8` и десериализовать в Python `dict`.
* Оставшиеся в буфере байты `SHALL` сохраняться для следующего чтения.
* Транспорт `SHALL` сверить `req_id` полученного ответа с `req_id` отправленного запроса. ЕСЛИ они не совпадают, `SHALL` выбросить исключение рассинхронизации.

## 5. Transport Exception Mapping (Обработка сетевых ошибок)

Транспортный слой не анализирует поле `status` и `error` из JSON (это задача логики API). Его ответственность — только сетевые инварианты.

* ЕСЛИ возникает `socket.timeout`, транспорт `SHALL` перехватить его и выбросить доменное исключение `VoxelTimeoutError`.
* ЕСЛИ возникает `ConnectionRefusedError` (сервер выключен), транспорт `SHALL` перехватить его и выбросить доменное исключение `VoxelConnectionError` с понятным сообщением (например, `"Не удалось подключиться к серверу. Убедитесь, что сервер запущен."`).
