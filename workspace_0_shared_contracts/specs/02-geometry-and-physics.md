# 02-geometry-and-physics: Геометрия Участков и Физика Границ

> **ABSTRACT:** Спецификация определяет математические инварианты виртуального пространства (Plot). Контракт задает преобразование пользовательской системы координат (User Space) в сетевую (Network Space), а также правила физической изоляции участков (Griefing Protection).

## 1. Plot Dimensions (Математика Участка)

Каждый Участок (Plot) `SHALL` представлять собой строго ограниченный 3D-объем (Bounding Box) со следующими константами:
* **Width (Ось X):** 32 блока.
* **Depth (Ось Z):** 32 блока.
* **Height (Ось Y):** 64 блока.
* **Floor Level:** Рабочая зона начинается строго с уровня $Y = 0$. Уход в отрицательные значения $Y$ `SHALL NOT` допускаться.

## 2. Coordinate Spaces & Virtual Shift (Смещение координат)

Для обеспечения комфортного пользовательского опыта (совместимость с классической школьной математикой 4-х четвертей), система `SHALL` реализовать семантическое разделение систем координат.

### 2.1. User Space (Пользовательское пространство)
* Используется учеником при написании кода.
* Точка отсчета `(0, 0, 0)` `SHALL` находиться в **центре** участка на уровне пола.
* Допустимые диапазоны: $X_{user} \in [-15..15]$, $Z_{user} \in [-15..15]$, $Y_{user} \in [0..63]$.

### 2.2. Network Space (Сетевое пространство)
* Используется при передаче JSON-координат в `[[01-network-transport]]`.
* Точка отсчета `(0, 0, 0)` `SHALL` находиться в **левом нижнем углу** участка.
* Допустимые диапазоны: $X_{net} \in [0..31]$, $Z_{net} \in [0..31]$, $Y_{net} \in [0..63]$.

### 2.3. Transformation Rule (Контракт преобразования)
* `[[Client Node]]` `SHALL` невидимо для конечного пользователя выполнять математический сдвиг перед отправкой сетевого пакета по формуле:
  * $X_{net} = X_{user} + 15$
  * $Z_{net} = Z_{user} + 15$
  * $Y_{net} = Y_{user}$
* `[[Server Node]]` `SHALL` оперировать исключительно координатами Network Space `[0..31]` и отклонять любые запросы, выходящие за эти пределы.

## 3. Boundary Physics (Защита границ и изоляция)

Для предотвращения гидродинамического терроризма (гриферства жидкостями) и случайного разрушения соседних участков, `[[Server Node]]` `SHALL` гарантировать физическую изоляцию каждого Участка.

* **Invisible Shield:** Сервер `SHALL` автоматически генерировать невидимый, неразрушаемый барьер по внешнему периметру Участка от высоты $Y=1$ до $Y=63$.
* **Containment Rules:** 
  * Любые сыпучие блоки (гравий, песок) `SHALL NOT` иметь возможности упасть за пределы Network Space `[0..31]`.
  * Текучие жидкости (вода, лава) `SHALL NOT` вытекать за границы барьера, даже если источник установлен на координате $X_{net} = 31$ или $Z_{net} = 31$.
* **Collision Check:** ЕСЛИ виртуальная сущность `Turtle` пытается переместиться за пределы Network Space `[0..31]`, `[[Server Node]]` `SHALL` заблокировать перемещение и вернуть ошибку выхода за границы.
