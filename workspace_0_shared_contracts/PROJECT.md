# PROJECT: Shared Protocol Contracts (Единый Контракт Взаимодействия)

> **ABSTRACT:** Данный файл является "Паспортом Системы". Он описывает фундаментальный смысл, бизнес-цели и макро-архитектуру экосистемы. ИИ-агенты `SHALL` использовать этот документ для понимания предметной области (Domain Knowledge) и предотвращения архитектурных галлюцинаций при работе с сетевыми контрактами.

## 1. System Passport (Бизнес-миссия: "Что и Зачем")

**Продукт:** Распределенная образовательная 3D-песочница (Троянский конь инфраструктуры).
**Целевая аудитория:** Школьники 11–14 лет (Создатели) и их окружение (Гости/Зрители).

**Глобальная цель (The Why):** 
Обучить детей концепциям ООП, алгоритмики, идемпотентности и распределенных систем. Система `SHALL NOT` являться просто "игрой". Код `SHALL` быть первичным (Infrastructure as Code), а воксельный 3D-мир `SHALL` выступать исключительно как терминал вывода (монитор) для визуализации исполнения этого кода. Успех системы измеряется тем, насколько легко ученик может написать скрипт на своем ПК и насколько быстро он может поделиться ссылкой на результат со своими друзьями (Zero-Install витрина).

## 2. Current Milestone: Stage 1 (MVP)

Текущий этап разработки строго ограничен рамками **MVP (Minimum Viable Product)** под девизом: *"Локальный код, глобальная витрина"*.

* **In Scope (Входит в MVP):** Локальное исполнение Python-кода, трансляция команд на сервер по TCP, базовая физика перемещений и установки блоков, изоляция Участков невидимыми барьерами, запись "пленки" для офлайн-просмотра зрителями из Wasm-браузера.
* **Out of Scope (КАТЕГОРИЧЕСКИ ИСКЛЮЧЕНО из MVP):** Блокчейн-транзакции, смарт-контракты, списание балансов криптовалют, федерация серверов (P2P), сторонние базы данных (PostgreSQL). Протокол `SHALL` содержать только JSON-заглушки (Extension Hooks) для этих функций.

## 3. Architectural Context (Макро-Архитектура)

Рабочее пространство `shared_contracts` является центральным нервным узлом. Контракты, описанные здесь, связывают три независимых физических узла:

1. **`[[Client Node]]` (Ученический ПК):** Запускает логику алгоритма. Ничего не знает о рендеринге 3D-графики.
2. **`[[Server Node]]` (Симуляция Luanti):** Находится в облаке. Принимает команды, валидирует их на законы физики и меняет состояние воксельного мира. Ничего не знает о том, на каком языке написана логика клиента.
3. **`[[Web Gateway]]` (Браузер Гостя):** Подключается к серверу для наблюдения за процессом. Ничего не знает о протоколах взаимодействия Клиента и Сервера.

Контракты этого рабочего пространства `SHALL` быть абсолютно абстрагированы от языков реализации (Language Agnostic).

## 4. Domain Glossary (Глоссарий Предметной Области)

Для сохранения терминологической чистоты, любые изменения в контрактах `SHALL` строго следовать данному глоссарию:

* **Plot (Участок):** Изолированный объем пространства (Bounding Box $32 \times 32 \times 64$ блока), выделенный одному Ученику для исполнения его кода.
* **Turtle (Черепашка / Бот):** Виртуальная 3D-сущность (Entity), которая материализует алгоритм Ученика на Участке.
* **User Space:** Система координат, комфортная для Ученика (центр участка = `0,0,0`).
* **Network Space:** Система координат, используемая в сетевом протоколе (левый нижний угол = `0,0,0`).
* **Record & Replay (Пленка):** Механизм сервера по записи шагов Черепашки в оперативной памяти для их последующего "проигрывания" Гостям, когда Ученик находится в офлайне.
* **Guest (Зритель):** Неавторизованный посетитель Wasm-витрины, ограниченный аппаратно (режим Spectator) правами только летать и нажимать интерактивные кнопки старта демо.
